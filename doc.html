Sistema MedLife
Clínica Médica

Documentação oficial do projeto desenvolvido em Java com Programação Orientada a Objetos. O sistema simula uma clínica médica com gerenciamento de pacientes, médicos, planos, agendamentos, contatos e serviços online.

Visão Geral

Sobre o projeto

O projeto MedLife foi criado para representar uma solução digital para uma clínica médica, aplicando conceitos de POO como classes, objetos, encapsulamento, herança, polimorfismo, interfaces, coleções, exceções customizadas e organização em camadas.

🎯

Objetivo

Desenvolver um sistema Java organizado, funcional e documentado para simular processos de uma clínica médica, como cadastro, consulta de planos e agendamento.

🏥

Tema escolhido

Clínica Médica: controle de pacientes, médicos, planos de saúde, agendamentos, contatos e serviços digitais.

☕

Tecnologia principal

Java com Programação Orientada a Objetos, executado no IntelliJ IDEA com estrutura de pacotes organizada.

Desafio

Problema que o sistema resolve

O sistema MedLife resolve a dificuldade de centralizar informações de uma clínica médica em um único ambiente digital, facilitando o acesso a planos, médicos, serviços, contatos e agendamentos.

⚠️

Problema identificado

Pacientes muitas vezes têm dificuldade para encontrar informações claras sobre planos, médicos disponíveis, canais de atendimento e serviços oferecidos pela clínica. Isso gera demora no atendimento, dúvidas repetidas e dependência de contato manual.

🏥

Contexto do negócio

A MedLife representa uma clínica médica que precisa organizar seus serviços digitais e melhorar a comunicação com pacientes e profissionais de saúde, mantendo as informações em uma plataforma simples, acessível e bem estruturada.

👥

Stakeholders

  • Pacientes que consultam planos, médicos e serviços.
  • Médicos e profissionais de saúde.
  • Equipe administrativa da clínica.
  • Setor de atendimento e suporte.
  • Equipe de desenvolvimento do sistema.
🔒

Restrições

  • O sistema deve ser desenvolvido em Java.
  • O projeto deve aplicar Programação Orientada a Objetos.
  • O código deve seguir a estrutura model, service, repository, exception, util e main.
  • A interface deve ser organizada, responsiva e fácil de navegar.

Pessoa é classe abstrata e possui especializações como Paciente e ProfissionalSaude.
Medico herda de ProfissionalSaude, formando dois níveis de hierarquia.
Paciente possui um Plano e pode ter vários Agendamentos.
AgendamentoService usa coleções List e Map para gerenciar consultas e médicos.
Repository<T>, Agendavel e Notificavel representam contratos por interface.

@startuml
title Sistema MedLife - Diagrama de Classes

abstract class Pessoa {
  - nome: String
  - cpf: String
  - email: String
  - telefone: String
  + exibirResumo(): String
  + validarDados(): boolean
}

class Paciente {
  - numeroCarteirinha: String
  - plano: Plano
  - historico: List<String>
  + solicitarAgendamento(): void
  + exibirResumo(): String
}

abstract class ProfissionalSaude {
  - registro: String
  - especialidade: String
  + atenderPaciente(): void
  + exibirResumo(): String
}

class Medico {
  - crm: String
  - agenda: List<Agendamento>
  + consultar(): void
  + listarHorarios(): List<String>
}

class Plano {
  - nome: String
  - tipo: String
  - cobertura: String
  - valor: double
  + calcularMensalidade(): double
  + exibirDetalhes(): String
}

class Agendamento {
  - paciente: Paciente
  - medico: Medico
  - dataHora: LocalDateTime
  - status: String
  + confirmar(): void
  + cancelar(): void
}

interface Agendavel {
  + agendar(): void
  + cancelarAgendamento(): void
  + verificarDisponibilidade(): boolean
}

interface Notificavel {
  + enviarNotificacao(): void
  + gerarMensagem(): String
}

interface Repository<T> {
  + salvar(T item): void
  + listar(): List<T>
  + buscarPorId(int id): T
  + remover(int id): void
}

class AgendamentoService {
  - agendamentos: List<Agendamento>
  - medicos: Map<String, Medico>
  + criarAgendamento(): void
  + cancelarAgendamento(): void
  + listarAgendamentos(): List<Agendamento>
}

class PlanoService {
  - planos: List<Plano>
  + listarPlanos(): List<Plano>
  + buscarPlano(String nome): Plano
  + adicionarPlano(Plano plano): void
}

Relatório Técnico

Decisões e justificativas

🧠

Decisões de projeto

  • Separação do projeto em três áreas principais: web, src e docs.
  • Organização do código Java em pacotes: model, service, repository, exception, util e main.
  • Uso de classes abstratas para representar entidades genéricas.
  • Uso de interfaces para contratos de agendamento, notificação e persistência.
  • Uso de coleções para simplificar a persistência durante a demonstração.
✅

Funcionalidades planejadas

  • Listagem de planos médicos.
  • Organização de médicos e especialidades.
  • Simulação de agendamento de consulta.
  • Páginas web separadas por área do site.
  • Servidor Java local para exibir a interface.
⚠️

Dificuldades encontradas

  • Separar corretamente front-end, backend e documentação.
  • Criar páginas diferentes mantendo o mesmo visual.
  • Planejar a aplicação dos conceitos de POO no backend Java.
  • Representar herança, interfaces, coleções e exceções de forma clara no UML.
📈

Métricas de qualidade

  • Código organizado por responsabilidade.
  • Nomes de classes e métodos claros.
  • Uso planejado de encapsulamento com atributos privados.
  • Baixo acoplamento entre camadas.
  • Documentação visual e textual integrada ao site.
Desafios Técnicos

Dificuldades e soluções aplicadas

Desafio Problema técnico Solução aplicada Aprendizado
Separar o site em páginas O projeto começou como uma página única com links internos. O site foi dividido em pastas como planos, serviços, documentação, notícias e contato. Melhor organização e navegação mais profissional.
Organizar o backend Era necessário deixar o Java estruturado para POO. Foi criada a estrutura src com model, service, repository, exception, util e main. Separação de responsabilidades facilita manutenção e avaliação.
Aplicar POO corretamente O projeto precisa demonstrar herança, polimorfismo, interfaces, coleções e exceções. Foi planejada uma modelagem com Pessoa, Paciente, Médico, Plano, Agendamento e Services. POO ajuda a representar entidades reais de forma mais clara.
Documentar o projeto Além do código, era necessário explicar decisões, UML, requisitos e cronograma. A pasta docs e a página de documentação centralizam as informações técnicas. Documentação melhora a apresentação e mostra domínio do projeto.

Manual do usuário

Como executar o projeto

Rodando no IntelliJ

  • Extrair o projeto ZIP.
  • Abrir a pasta principal no IntelliJ IDEA.
  • Acessar src/main/Main.java.
  • Clicar em Run.
  • Abrir no navegador: http://localhost:8080.

Navegação do site

  • Início: visão geral da MedLife.
  • Planos: opções de planos médicos.
  • Serviços: funcionalidades digitais.
  • Guia Médico: busca de profissionais.
  • Documentação: UML e relatório técnico.
  • Contato: canais de atendimento.
Observação: para funcionar no Google Sites com backend Java, o projeto precisa estar hospedado em um servidor público com HTTPS. Rodando apenas em localhost, ele funciona somente no computador local.
